# Работа с данными

Поиск, обоснование, описание и протокол подготовки данных для системы генерации
и оценки рифмованной русской поэзии.

## 1. Поиск и обоснование

**Требования к данным проекта:**
- русскоязычная поэзия (силлабо-тоника), строфы с регулярной рифмовкой;
- желательна разметка: ударения, схема рифмовки, метр (для обучения/валидации
  детектора рифмы);
- открытая лицензия, пригодная для исследовательского использования;
- достаточный объём и разнообразие авторов/эпох (чтобы метрики не переобучались
  на одном стиле).

**Зачем именно эти данные.** Для *оценки* детектора рифмы нужна разметка
рифм/ударений → ключевые `Rifma` и `ArsPoetica` (Koziev), совместимые с RPST.
Для *генерации* и языкового разнообразия — крупные неразмеченные корпуса
(`stihi_ru`, НКРЯ-поэтический, PULPO). Мультиязычные/англ. корпуса (Gutenberg
Poetry) — для кросс-языковых экспериментов и сравнения с зарубежным SOTA.

## 2. Описание наборов данных (кандидаты)

| Датасет | Язык | Объём | Разметка | Лицензия | Источник |
|---|---|---|---|---|---|
| **Rifma** | RU | 5002 фрагмента | ударения + схема рифмовки | см. репо | https://github.com/Koziev/Rifma |
| **ArsPoetica** | RU | ~8.5k стихов | ударения | см. карточку | https://huggingface.co/datasets/inkoziev/ArsPoetica |
| **stihi_ru** (Gusev) | RU | крупный корпус | нет (сырой текст) | см. карточку | https://huggingface.co/datasets/IlyaGusev/stihi_ru |
| **Поэтический подкорпус НКРЯ** | RU | большой | метр/рифма/строфика + морфология | усл. НКРЯ | https://ruscorpora.ru/page/corpus-poetic-index/ |
| **PULPO** | мультиязычный (вкл. RU) | >72–95M слов | нет (сырой) | см. карточку | https://huggingface.co/datasets/linhd-postdata/pulpo |

> Объёмы/лицензии указаны по карточкам источников — перед использованием
> сверить актуальные условия (особенно НКРЯ и HF-датасеты).

**Основной выбор для ВКР:**
- обучение/тюнинг детектора рифмы и его валидация → **Rifma + ArsPoetica**;
- языковое разнообразие и генерация → **stihi_ru** (+ НКРЯ-поэтический при
  доступе);
- кросс-язык/сравнение → **PULPO**, **Gutenberg Poetry**.

## 3. Описание источников (provenance)
- **Koziev (Rifma, ArsPoetica, RPST, NLP_Datasets)** — автор RPST; разметка
  совместима с инструментом, что снижает рассогласование форматов
  (https://github.com/Koziev/NLP_Datasets).
- **НКРЯ** — академический корпус с профессиональной стиховедческой разметкой;
  доступ по условиям корпуса (некоммерческое исследовательское использование).
- **Hugging Face (stihi_ru, ArsPoetica, PULPO)** — лицензия и происхождение
  указаны в карточках; stihi_ru собран с публичной площадки stihi.ru —
  требуется проверка прав на тексты конкретных авторов.
- **Project Gutenberg (Gutenberg Poetry)** — общественное достояние, CC0.

⚠️ **Лицензионная чистота:** тексты современных авторов (stihi.ru и т.п.) могут
быть защищены авторским правом. Для ВКР приоритет — public domain (классика) и
датасеты с явной открытой лицензией; современные тексты использовать только в
агрегированном/метрическом виде или с разрешения.

## 4. Предобработка
Пайплайн (частично реализован в `src/Model/TextConverter.py`):
1. **Нормализация:** UTF-8, приведение к нижнему регистру, удаление пунктуации
   (для детектора), разбиение на строки и слова. Сохранение исходного варианта
   с пунктуацией/регистром — для показа и разметки клаузул.
2. **Сегментация на строфы:** по пустой строке; фильтр строф длиной ≥2 строк.
3. **Дедупликация:** удаление точных и near-duplicate строф (хэш/шингл).
4. **Фильтрация:** язык (русский), длина, кодировка, отсев технического мусора.
5. **Разметка ударений** (RPST) → хвосты/клаузулы; для размеченных датасетов —
   сверка с эталоном.
6. **Формирование примеров:** (строфа, целевая схема, метки рифмующихся пар).
7. **Разбиение** train/val/test со стратификацией по схеме рифмовки и размеру;
   фиксация random seed и версии датасета.

## 5. Протокол сбора данных
1. **Источники и права:** фиксировать происхождение и лицензию каждого текста;
   для PD — указывать автора/издание; для HF/НКРЯ — ссылку на карточку и условия.
2. **Сбор:** использовать готовые датасеты (предпочтительно) вместо парсинга;
   при парсинге — соблюдать robots.txt и условия площадки, хранить дату выгрузки.
3. **Очистка:** нормализация (см. §4), дедупликация, отсев не-русских/битых
   фрагментов.
4. **Разметка:** автоматическая (RPST: ударения, метр, рифма) + выборочная
   ручная проверка ≥2 аннотаторами; согласие — Cohen's κ.
5. **Версионирование:** каждый релиз датасета — с версией, хэшем и описанием
   изменений; неизменяемые train/val/test split'ы.
6. **Метаданные:** на каждый пример — источник, лицензия, схема, размер, метки.
7. **Хранение:** сырые/обработанные данные раздельно; крупные файлы — вне git
   (LFS или внешнее хранилище), в репо — только скрипты и манифесты.

Формальные требования к пайплайну и метрики оценки — в
