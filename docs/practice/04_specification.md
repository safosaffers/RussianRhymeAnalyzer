# Спецификация

Формальная постановка задачи, метрики качества, требования к окружению и
пайплайн данных для системы ИИ-генерации и оценки рифмованной русской поэзии.
Опирается на реализованный прототип (приложение «Rhymer», см.
[../ARCHITECTURE.md](../ARCHITECTURE.md), [../RHYME_DETECTOR.md](../RHYME_DETECTOR.md)).

## 1. Математическая постановка

### 1.1. Обозначения
- Параметры запроса: θ = (t, p, L, s) — тема t, размер p (ямб/хорей/…),
  число строк L, схема рифмовки s (напр. ABAB).
- Стихотворение y = (ℓ₁, …, ℓ_L) — последовательность строк;
  строка ℓ_i разбивается на слоги σ_(i,1), …, σ_(i,n_i).
- Генератор G_φ — языковая модель, y ~ G_φ(·|θ).
- Детектор рифмы D: D(y, s) → m — словарь метрик (см. §2).

### 1.2. Целевая функция (генерация)
Качество кандидата оценивается ранжирующим баллом
R(y,θ) = 0,6·ρ(y) + 0,4·min(max(q(y),0),1),
где ρ(y) — доля зарифмованных слогов (`rhyme_percent`),
q(y) — поэтичность RPST (`score`). Для детектора Юкавы R = ρ(y).

**Best-of-N.** Генерируем N кандидатов и выбираем лучший:
y* = argmax_{y∈{y⁽¹⁾,…,y⁽ᴺ⁾}} R(y,θ), где y⁽ᵏ⁾ ~ G_φ(·|θ).

**Самокоррекция.** Если у лучшего кандидата точность по схеме A(y*,s) < 1,
строится текстовый фидбэк F(m) и запрашивается одна правка
y′ = G_φ(·|y*, F(m), θ); в выбор добавляется y′.

### 1.3. Детекция рифмы — формализация
**Хвост и созвучие (RPST-ветвь).** Для строки с разметкой ударения — хвост
τ_i = подстрока от последней ударной гласной до конца. Степень созвучия
match(τ_a, τ_b) ∈ {0, 0,6, 0,9, 1,0} по совпадению ударной
гласной и согласного «скелета». Точность по схеме:
A(y,s) = #{(a,b): s_a=s_b, match(τ_a,τ_b) ≥ 0,5} / #{(a,b): s_a=s_b}.

**Граф связей (ветвь Юкавы).** Узлы — слоги. Сила связи слогов a, b:
S_ab = sim(a,b)·K_λ(d_ab)·|E_a·E_b|/η, ядро экранирования
K_λ(d) = e^(−λd)/d,
где d_ab — манхэттенское расстояние по решётке (строка, позиция),
sim — созвучие (гласная + общие согласные), E — «энергия» слога,
η — нормировка. После резонанса
S′_ab = S_ab + γ·(1/N)·Σ_c S_ac·S_bc и нормировки берутся рёбра
S′_ab ≥ β·max S′; компоненты связности = группы рифм.
Параметры (λ, γ, β, η, …) настраиваемы (см. `DEFAULTS`).

### 1.4. Тип модели и допущения
- Тип: генератор — предобученная авторегрессионная LLM (без дообучения на
  прототипе; дообучение/RL — направление ВКР); детектор рифмы — не обучаемый
  (правила + готовая модель ударений RPST + графовый алгоритм).
- Допущения: входной язык — русский; силлабо-тоническое стихосложение;
  слогораздел = «одна гласная на слог»; рифма опирается на ударную гласную и
  согласный скелет.
- Ограничения: детектор Юкавы шумит на длинных текстах; качество генерации
  зависит от внешнего API; RPST-разметка ударений может ошибаться на
  редких/омографичных словах.

## 2. Метрики качества

| Метрика | Определение | Назначение |
|---|---|---|
| `rhyme_accuracy` A(y,s) | доля верно срифмованных пар по схеме | основная для генерации |
| `rhyme_percent` ρ(y) | доля слогов в подсвеченных рифмах | ранжирование, наглядность |
| RPST `score` q(y) | поэтичность по RPST | компонент R |
| meter accuracy | доля строк с корректным размером | контроль размера |
| scheme match | совпадение `detected_scheme` с целевой s | контроль схемы |
| **(оценка детектора)** precision/recall групп рифм vs разметка | TP/(TP+FP), TP/(TP+FN) | валидация детектора на размеченном корпусе |
| **(оценка детектора)** корреляция с экспертной оценкой | Spearman ρ_s | согласие с человеком |

Протокол оценки: на размеченном тест-наборе (схема + рифмующиеся пары)
считаем precision/recall детекции рифм; на сгенерированных стихах — A, meter
accuracy и экспертную шкалу 1–5 (≥2 аннотатора, согласие по Cohen's κ).

## 3. Требования к окружению

| Компонент | Версия/значение |
|---|---|
| ОС | Linux (разработка); кроссплатформенно (PySide6) |
| Python | 3.12 (venv) |
| GUI | PySide6 6.11 |
| Анализ стиха | `russian_scansion` (RPST) 1.0.22 + модели (LFS) |
| Научный стек | numpy, scipy, matplotlib, torch 2.10 |
| LLM SDK | `anthropic` (Claude) и/или `openai` (Gemini/DeepSeek через OpenAI-совместимый API) |
| Переменные окружения | `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` / `DEEPSEEK_API_KEY`, `RHYMER_PROVIDER`, `RHYMER_MODEL` |
| Архитектура | MVP (Model/View/Presenter), тяжёлые задачи в QThread |
| Ресурсы | CPU достаточно; модели RPST грузятся ~15–30 с (кэшируются на процесс) |

Подробности подключения LLM — [../LLM_SETUP.md](../LLM_SETUP.md).

## 4. Пайплайн данных

```
сбор корпуса (poems/, открытые источники)
        │  нормализация (TextConverter: lower, без пунктуации, split строки/слова)
        ▼
дедупликация + фильтрация (длина строф, язык, кодировка UTF-8)
        │  разметка ударений (RPST) — хвосты/клаузулы
        ▼
формирование примеров (строфа, схема, метки рифмующихся пар)
        │  split train/val/test (стратификация по схеме/размеру)
        ▼
оценка: детектор рифмы D — метрики §2 ; для генерации — best-of-N + самокоррекция
        │
        ▼
логи экспериментов (параметры, метрики, версии моделей) — таблицы для ВКР
```

Для прототипа источник данных — корпус `poems/` (русская классика) +
генерация-заглушка из него; для ВКР — расширенный датасет (см.
[03_data.md](03_data.md)) с протоколом сбора и лицензионной чистотой.
