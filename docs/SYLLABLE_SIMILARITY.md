# Схожесть слогов: фонетическая векторизация

Модуль `src/Model/Phonetics.py`. Отвечает на вопрос «насколько созвучны два
слога» — это базовый кирпич детектора Юкавы (из него строится матрица связей,
а из неё — группы рифм).

## Зачем переписали

Раньше слог сворачивался в одно число — «энергию» по **порядку буквы в
алфавите** (`а=1.0, о=2.0 … и=6.0`) с множителями за звонкость. Число без
фонетического смысла: близость `а`/`я` и далёкость `а`/`и` из него не следуют,
а сравнение слогов сводилось к «гласная совпала / не совпала» (бинарно) плюс
доля общих согласных.

Новый подход — приём из курса **«Обработка текстов на естественном языке»**:
каждый слог кодируется **вектором фонетических признаков** (артикуляционная
фонетика), а схожесть = **косинус** между векторами. Тогда выполняется главное
свойство векторизации — *похожие по звучанию слоги имеют похожие векторы*:

- основной вклад в созвучие даёт **гласная** (ядро рифмы);
- **согласные** тоже вносят вклад: слоги с разными гласными, но общими
  согласными остаются частично похожими — это ловит **аллитерацию/консонанс**.

## Вектор слога

`syllable_vector(syl)` возвращает **два блока** — отдельно гласную и согласные,
чтобы их вклад можно было взвешивать независимо.

### Блок гласной (9 признаков)

```
[ one-hot класса звука: a o u y e i ] ++ [ передний_ряд, подъём, огубленность ]·0.35
            вес 1.0 (доминирует)                 артикуляционный нюанс
```

- **one-hot класса.** Гласные группируются по *звуку*: йотированные дают тот же
  звук — `я→a, ё→o, ю→u, е→e`. Поэтому `на`/`ня` почти совпадают (различие лишь
  в мягкости, см. ниже), а совпадение самого звука гласной даёт косинус ≈ 1.
- **артикуляция** (передний ряд / подъём / огубленность ∈ [0,1], малый вес 0.35)
  добавляет *мягкую* близость разных гласных: `о`/`у` — задние огубленные, потому
  чуть ближе друг к другу, чем к `и`. Малый вес гарантирует, что это нюанс, а не
  основной сигнал — разные гласные всё равно заметно менее похожи, чем равные.

### Блок согласных (12 + 1 признаков)

«Мешок фонетических признаков» — сумма векторов всех согласных слога. Признаки:

```
[ звонкость, сонорность,
  губной, зубной, шипящий, велярный, палатальный,      ← место образования
  взрывной, фрикативный, аффриката, носовой, плавный ] ← способ образования
+ [ мягкость ]·0.5   (палатализация: йотированная гласная или «ь»)
```

Звонкая/глухая пара (`з`/`с`, `б`/`п`, `г`/`к` …) совпадает по месту и способу
образования, различаясь лишь одним признаком звонкости → высокий косинус → пара
ловится как созвучие, а не как разные звуки. Суммирование (а не множество)
естественно усиливает повторяющиеся согласные.

## Схожесть

```python
syllable_similarity(s1, s2, vowel_weight=0.6) =
      vowel_weight      · cos(блок_гласной_1, блок_гласной_2)
  + (1 − vowel_weight)  · cos(блок_согласных_1, блок_согласных_2)
```

Результат в `[0, 1]` (все признаки неотрицательны, поэтому косинус ≥ 0 — порог
`link_ratio` в детекторе остаётся осмысленным). Пустой блок (слог без согласных)
считается совпадающим с другим пустым и несовпадающим с непустым.

`vowel_weight` (по умолчанию `0.6`) — ручка «гласная важнее согласных»; настраивается
из UI живьём.

### Примеры (vowel_weight = 0.6)

| пара | sim | почему |
|---|---|---|
| `кро` / `кро` | **1.00** | полное совпадение |
| `на` / `ня`  | **0.99** | та же гласная-звук `a`, отличие лишь мягкость |
| `зо` / `со`  | **0.93** | та же гласная + звонкая/глухая пара `з`/`с` |
| `бы` / `ба`  | **0.41** | та же согласная `б`, разные гласные → аллитерация |
| `на` / `но`  | **0.40** | та же согласная `н`, разные гласные → аллитерация |
| `кро` / `тя` | **0.22** | почти всё разное |
| `ро` / `та`  | **0.14** | разное (лёгкое пересечение по «зубной») |

## Энергия слога

`syllable_energy(syl, voiced_mult=2.0, voiceless_mult=0.5)` — «масса» слога для
весов связей в матрице (пары «тяжёлых» слогов связаны сильнее). Тоже выведена из
признаков, без алфавитного порядка:

```
энергия = сонорность_гласной · (1 + Σ масса_согласного)
          сонорность: a=1.0, o/e=0.85, y/u/i=0.7
          масса согласного: voiced_mult если звонкий, иначе voiceless_mult
```

`voiced_mult` / `voiceless_mult` остаются настраиваемыми из UI.
