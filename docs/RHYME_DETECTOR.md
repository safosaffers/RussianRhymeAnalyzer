# Детекторы рифмы

В приложении два взаимозаменяемых детектора с единым интерфейсом
`evaluate(text, scheme[, params]) -> dict` (выбор — параметром `method`):

1. **RPST** (`RhymeEvaluator`) — надёжный, на готовой модели разметки ударений.
2. **Юкава** (`YukawaDetector`) — авторский алгоритм по физической метафоре
   (новизна для ВКР).

Прототип-исследование авторского подхода — `src/Research/detector.py` (со
spectral-визуализацией matplotlib); рабочее ядро из него вынесено в
`src/Model/YukawaDetector.py`.

---

## 1. RPST-детектор (`RhymeEvaluator`)

Обёртка над `RussianPoetryScansionTool` (пакет `russian_scansion`). RPST
размечает ударения, определяет размер, схему рифмовки и поэтичность `score`.
Поверх размеченных ударений считается собственная метрика рифмовки.

Конвейер `evaluate`:
1. `tool.align(lines)` → ударения (`get_stressed_lines`), `score`, `meter`,
   `rhyme_scheme`. Модели грузятся лениво (`_ensure`, один раз на процесс) —
   с явным `models_dir` (обход бага `joinpath('')` на Python 3.12).
2. **Рифмующийся хвост** строки (`rhyme_tail`) = от последней ударной гласной
   до конца. Ударение в выводе RPST помечено `U+0301` сразу после гласной;
   при отсутствии разметки — фоллбэк на последнюю гласную.
3. **Сравнение хвостов** (`rhyme_match`) — дискретно 0 / 0.6 / 0.9 / 1.0:
   опора на ударную гласную + согласный «скелет» после неё (финальная
   безударная гласная может отличаться: *единственный / таинственной*).
4. **Точность по схеме** (`scheme_accuracy`): схема (`ABAB`/`AABB`/`ABBA`)
   разворачивается под число строк, считается доля верно срифмованных пар.
   `detected_scheme` — лучшая из типовых схем.
5. **Подсветка** (`analyze_rhyme_coloring`): строки группируются по созвучию
   клаузул (`group_rhymes`), каждой группе ≥2 — цвет из `RHYME_COLORS`.
   `rhyme_percent` = слоги в подсвеченных клаузулах / все слоги.
6. **Итоговый балл**: `rhyme_score = 0.6·rhyme_percent + 0.4·clamp(score,0,1)`.

## 2. Авторский детектор Юкавы (`YukawaDetector`)

Идея: стих — это **расслоённое пространство над решёткой**, а рифма — мера
«взаимодействия» слогов. Сила взаимодействия складывается из созвучия слогов,
их «энергии» и затухает с расстоянием по закону экранированного потенциала
**Юкавы**. Из получившейся матрицы связей выделяются группы рифм.

### Конвейер ядра

**1. Решётка слогов.** `split_into_syllables`: слог = одна гласная +
предшествующие согласные. Каждый слог — узел `(строка i, позиция j, текст)`.

**2. Энергия слога** (`syllable_energy`) — «эффективная масса»:
- база по гласной: `а=1.0, я=1.2, о=2.0, ё=2.2, у=3.0, ю=3.2, ы=4.0, э=5.0,
  е=5.2, и=6.0`;
- звонкие согласные `бвгджзлмнр` → ×2.0, глухие `пфктшсхцчщ` → ×0.5;
- `ь/ъ` → сдвиг +0.5;
- `энергия = база · произведение_множителей + сдвиг`.

**3. Матрица связей S.** Для каждой пары слогов `(a, b)`:

```
S[a,b] = similarity(a,b) · kernel(d) · energy_factor(a,b)
```

- `syllable_similarity` = `vowel_weight`·(совпала гласная) +
  `(1−vowel_weight)`·(доля общих согласных);
- `yukawa_kernel(d, λ) = e^(−λd)/d` — экранирование: гасит дальние связи
  (`d` — манхэттенское расстояние по решётке);
- `energy_factor = |E_a·E_b| / energy_div` — пары «тяжёлых» слогов связаны
  сильнее.

Затем **резонанс** (`apply_resonance`, γ): тройные корреляции — связь усиливается,
если у пары есть общие «друзья» (ритмический рисунок). Матрица нормируется.

**4. Группы рифм.** Из S берутся связи `≥ link_ratio · peak`; через
union-find выделяются **компоненты связности** = группы созвучных слогов
(размер ≥2). Каждой группе — цвет из `RHYME_COLORS`. `rhyme_percent` =
зарифмованные слоги / все слоги.

### Что изменилось vs прототип `detector.py`

Прототип после построения S делал **спектральное вложение** через
нормализованный лапласиан `L = I − D^(−1/2)·S·D^(−1/2)`, брал 3 младших
собственных вектора как RGB и рисовал тепловые карты (`poem_analysis.png`).
В приложении это заменено на выделение **компонент связности по порогу** —
дискретные группы рифм с цветами, совместимыми с RPST-подсветкой.

### Настраиваемые параметры (`DEFAULTS`)

Все константы вынесены в `DEFAULTS` и переопределяются через
`evaluate(..., params=...)` — для живого тюнинга из UI (`Presenter.on_tune`):

| параметр | смысл | дефолт |
|---|---|---|
| `use_distance` | учитывать экранирование по расстоянию | `True` |
| `lam` (λ) | сила экранирования (↑ → дальние связи слабее) | `0.8` |
| `gamma` (γ) | вес резонанса (общие «друзья») | `0.3` |
| `link_ratio` | порог рифмы как доля от максимума связи | `0.6` |
| `vowel_weight` | вес совпадения гласной в схожести | `0.6` |
| `use_energy` | домножать связь на энергии слогов | `True` |
| `energy_div` | делитель произведения энергий | `10.0` |
| `voiced_mult` / `voiceless_mult` | множители энергии для звонких/глухих | `2.0` / `0.5` |

## Сравнение

| | RPST | Юкава |
|---|---|---|
| основа | модель разметки ударений | физическая метафора (без ML) |
| единица | строка (хвост/клаузула) | отдельный слог |
| сильные стороны | надёжность, размер/схема/score | новизна, тонкая настройка, послоговая карта |
| слабые стороны | медленная первая загрузка моделей | шумит на больших текстах |

Оба возвращают общий контракт (`rhyme_score`, `rhyme_percent`,
`colored_lines`, `legend`, …) — см. [ARCHITECTURE.md](ARCHITECTURE.md).
